1. Project Overview

LGS-LLM is an intelligent exam generation system designed to create custom English language questions for the Turkish national high school entrance exam (LGS). The system leverages Large Language Models (LLM) to generate high-quality, pedagogically sound questions that match the difficulty and style of actual LGS exams.

Key Features:
  • AI-powered question generation using Groq's llama-3.3-70b-versatile model
  • AI image generation with Chroma and Zimage models
  • Real-time streaming of generated questions to frontend
  • Support for text and visual (image-based) questions
  • Priority generation: text questions first for faster initial display
  • Random distribution of visual questions across topics
  • PDF export with two options: with images or text-only
  • Per-session JSON logging with timestamps
  • Categorized debug output ([DEBUG], [DEBUG IG], [WARNING], [ERROR])
  • MongoDB integration for storing reference questions and metadata
  • CEFR A1-A2 English level questions (8th grade standard)
  • 10 distinct English learning units with specialized vocabulary

7. Question Generation Pipeline

Complete Flow from Request to Display

  1. Frontend sends request:

    User clicks "Quick Start" or "Start Exam" after selecting distribution.

    POST /generate-exam with distribution and visualCount

  2. Backend receives request:

    Backend calculates visual distribution (random allocation to topics)

    Creates visual_indices map: which questions in each topic should be visual

  3. Question generation starts:

    For each topic in distribution:

    • For each question count for that topic:
    • Check if this question should be visual
    • Call generate_question_for_unit(topic, visual=is_visual)
  4. LLM generates question:

    LLM receives:

    • System prompt (MASTER_SCHEMA with CEFR A1-A2 guidelines)
    • Unit name and vocabulary glossary
    • Example questions from database
    • Prompt template (TEXT_QUESTION_TEMPLATE or VISUAL_QUESTION_TEMPLATE)

    LLM outputs structured JSON with question data

  5. Process visual questions:

    If visual=True:

    • Extract image_prompt from generated question
    • Call generate_image_from_prompt(image_prompt)
    • Set imageUrl in question object
  6. Add metadata:

    Add to each question:

    • id (q1, q2, q3...)
    • topic
    • hasImage (boolean)
    • imageUrl
  7. Stream to frontend:

    Encode as JSON and yield with newline delimiter

    Small delay (0.5s) between questions

  8. Frontend receives and displays:

    Parse NDJSON line by line

    Increment loadingCount (updates progress bar)

    Add to questions array and sort by id

    Render in QuestionCard component

8. Question Data Formats

LLM Generated Question Format

Questions returned by the LLM follow this structure:

{ "unit": "Friendship", "type": "text", "question": { "passage": "Sarah and Mike are best friends...", "stem": "What does Emily suggest they do?", "options": { "A": "Go to the cinema", "B": "Have a picnic", "C": "Play video games", "D": "Study together" }, "answer": "B" }, "distractor_logic": { "Wrong_Letter_1": "Logic trap - 'but' changes meaning", "Wrong_Letter_2": "Role reversal trap", "Wrong_Letter_3": "Irrelevant vocabulary" } }

Visual Question Format

Visual questions include an image_prompt field:

{ "unit": "In The Kitchen", "type": "visual", "image_prompt": "A busy kitchen scene with...", "question": { "passage": "", "stem": "What is being prepared in the kitchen?", "options": {...}, "answer": "C" }, "distractor_logic": {...} }

Frontend Enhanced Format

Backend adds metadata before streaming:

{ ...(all LLM fields), "id": "q1", "topic": "Friendship", "hasImage": false, "imageUrl": null }

11. LLM Integration Details

Groq API Setup

  • Provider: Groq (groq.com)
  • Model: llama-3.3-70b-versatile
  • API Authentication: API key stored in environment

Prompt Engineering

MASTER_SCHEMA (System Prompt)

Establishes guidelines for question generation:

  • CEFR A1-A2 English level (8th grade)
  • Focus on Present Simple, Past Simple, "be going to", basic Modals
  • Context-driven questions (dialogues, invitations, posters)
  • LGS exam style (preferences and reasons)
  • Distractor logic patterns

TEXT_QUESTION_TEMPLATE

Used for text-based questions:

  • Includes unit name, vocabulary glossary, example questions
  • Instructs LLM to return JSON with passage, stem, options, answer
  • Requests distractor explanations

VISUAL_QUESTION_TEMPLATE

Used for image-based questions:

  • Includes image_prompt field for image generation
  • Same structure as text, but with visual context
  • Image prompt describes what image to generate

JSON Response Handling

Response Format:

LLM is configured to return JSON objects using response_format={"type": "json_object"}

Backend parses JSON string response and validates structure

If parsing fails, question is skipped with error logging

12. Image Generation System

Current Implementation

The image generation system supports two AI models for generating educational illustrations:

Chroma Model

Located in: backend/image_generation/chroma_client.py

  • Type: High-quality educational illustration model
  • Features: Positive/negative prompt engineering
  • Parameters: Configurable seed, steps, guidance scale
  • Output: Base64-encoded image data
Zimage Model

Located in: backend/image_generation/z_image_client.py

  • Type: Fast image generation model
  • Features: Single prompt approach
  • Parameters: Configurable dimensions
  • Output: Base64-encoded image data

Prompt Engineering

Each model has dedicated prompt engineering classes:

# ChromaPromptEngine - Generates positive prompts (scene description) - Generates negative prompts (elements to avoid) - Optimized for educational illustrations # ZimagePromptEngine - Single prompt generation - Optimized for the Zimage model style

Configuration

Set the image generation model in environment:

IMAGE_GENERATION_MODEL=chroma # or "zimage" CHROMA_API_URL=your_chroma_api_url ZIMAGE_API_URL=your_zimage_api_url

Visual Question Distribution

Visual questions are randomly distributed across topics:

  • User specifies total visual count in request
  • Backend randomly assigns visual count to topics
  • Within each topic, questions are randomly selected for visual rendering
  • Ensures visual questions don't cluster on first questions

12.1 Session Logging System

Overview

Every exam generation request creates a comprehensive JSON log file for debugging and analytics.

SessionLogger Class

Located in: backend/session_logger.py

  • Log Directory: backend/logs/
  • Filename Format: YYYY-MM-DD_HH-MM-SS-mmm.json
  • Auto-saves: After each logged event

Logged Information

  • Session metadata: Timestamp, distribution, visual count
  • Visual assignments: Which topics/indices get images
  • Generated questions: Full question data (without base64 images)
  • Image generation: Topic, index, prompt used
  • Errors: Any errors during generation
  • Completion status: Total questions generated

Log File Structure

{ "session_id": "2026-01-01_18-30-45-123", "timestamp": "2026-01-01T18:30:45.123456", "distribution": {"Friendship": 2, "Science": 1}, "visual_count": 1, "visual_indices": {"Friendship": [1]}, "questions": [...], "images_generated": [...], "errors": [], "completed": true, "total_questions": 3 }

Debug Print Categories

Console output is categorized for easier debugging:

  • [DEBUG] - General debug information
  • [DEBUG IG] - Image generation debug info
  • [WARNING] - Non-critical warnings
  • [ERROR] - Error messages

12.2 PDF Export System

Export Options

Users can download exams in two formats via a dropdown menu:

12.3 Priority Question Generation

Overview

Text questions are generated and streamed before visual questions for faster initial display.

How It Works

  1. Backend receives distribution with visual count
  2. Questions are sorted: text first (is_visual=False), visual last (is_visual=True)
  3. Text questions stream immediately to frontend
  4. Visual questions generate with images afterward
  5. User sees content faster while images process in background

Performance Impact

Question Type Generation Time
Text Question 1-3 seconds
Visual Question (with image) 5-15 seconds

By prioritizing text questions, users see initial results within seconds rather than waiting for image generation.

13. Progress Tracking & UI Updates

Frontend Progress Calculation

The progress bar and counter are based on loadingCount state:

  • loadingCount: Incremented each time a question arrives
  • totalQuestions: Sum of all counts in distribution
  • Progress %: (loadingCount / totalQuestions) * 100 (capped at 100%)

Real-time Updates

The UI updates in real-time as:

  1. Each question line is parsed from NDJSON stream
  2. loadingCount increments immediately
  3. Progress bar and counter display update
  4. Question is sorted and added to questions array
  5. QuestionCard component renders question

Loading States

  • Loading: Progress bar visible, "Sorular oluşturuluyor..." message
  • Complete: Progress bar hidden, "PDF İndir" button appears

15. Setup & Deployment

Prerequisites

  • Python 3.9+
  • Node.js 18+
  • MongoDB Atlas account (or local MongoDB)
  • Groq API key (from groq.com)

Backend Setup

  1. Navigate to backend directory: cd backend
  2. Install dependencies: pip install -r requirements.txt
  3. Set environment variables:
    • GROQ_API_KEY - Your Groq API key
    • MONGO_URI - MongoDB connection string (optional)
  4. Start server: python generate_exam.py
  5. Server runs on: http://localhost:8000

Frontend Setup

  1. Navigate to frontend directory: cd frontend
  2. Install dependencies: npm install or pnpm install
  3. Start development server: npm run dev
  4. Application runs on: http://localhost:3000

Quick Start

Run the provided PowerShell script to start both servers:

.\start_servers.ps1

17. Troubleshooting & Common Issues

Backend Issues

Port 8000 Already in Use

Solution: Change port or kill existing process
# Windows taskkill /F /IM python.exe # Linux/Mac lsof -ti:8000 | xargs kill -9

Groq API Key Not Found

Solution: Set environment variable
# Windows set GROQ_API_KEY=your_key_here # Linux/Mac export GROQ_API_KEY=your_key_here

MongoDB Connection Failed

Solution: Check MongoDB URI and network access
  • Verify MongoDB Atlas connection string
  • Check IP whitelist in MongoDB Atlas
  • Ensure internet connection

Frontend Issues

Questions Not Loading

Solution: Check backend connection
  • Verify backend is running on http://localhost:8000
  • Check browser console for network errors
  • Clear browser cache and reload

Progress Bar Not Updating

Solution: Progress uses loadingCount, ensure streaming is working
  • Open Network tab in DevTools
  • Check /generate-exam request for data chunks
  • Verify NDJSON format is correct

18. Performance Considerations

Optimization Strategies

  • Question Caching: Database questions are fetched once and cached in memory
  • Streaming: NDJSON format allows progressive question display without waiting for all to generate
  • Async Processing: FastAPI's async/await enables concurrent requests
  • LLM Latency: Groq API averages 1-3 seconds per question generation

Expected Generation Times

Number of Questions Estimated Time (Text Only) Estimated Time (With Images)
1-2 questions 2-6 seconds 7-20 seconds
5 questions (1 per topic) 7-15 seconds 30-75 seconds
10 questions 12-30 seconds 60-150 seconds
20+ questions 30-60+ seconds 2-5+ minutes
Priority Generation: Text questions are generated and displayed first, so users see initial results quickly while image generation continues in the background.

Database Performance

  • MongoDB Atlas connection established on first request
  • All 70 questions cached in memory after first fetch
  • Subsequent requests use cached data (no database hits)
